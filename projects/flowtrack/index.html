Product Design

FlowTrack

FlowTrack is a project and task management platform with a dashboard, task boards, team membership, calendar, submissions, activity and chat routes. The task model supports ownership, status, priorities and due dates, so teams can see work that is planned, in progress, completed or overdue.

View editable UI referencesView source code

Problem space

When team tasks, deadlines, comments and ownership live in separate tools, it is difficult to see what is moving, what is blocked and who needs follow-up. FlowTrack brings project status and collaboration into a shared workspace.

Design approach

I focused the board on clear task states and team context. Project metrics make the workload scannable, while task cards keep the title, category, assignee and due-date information together. The calendar gives a second view for deadlines and team commitments, complementing the board rather than replacing it.

Key design decisions

  • Use visible task columns to make status and work-in-progress easier to scan.
  • Keep assignee, category and due date on the task card so basic decisions do not require opening every task.
  • Pair the Kanban board with a calendar for deadline-based planning.
  • Keep activity and collaboration routes in the same workspace as project tasks.
  • Design empty, loading, permission and task-move failure states before relying on the board in team workflows.

Product screens

This is a concept design. Amounts shown are sample interface content, not live financial data. The Invest tab is shown as unavailable until a licensed investment partner is connected.

What I would validate next

I would validate the board with teams using realistic task volumes and test dragging tasks between states, task ownership changes, invitations, empty boards, overdue states, mobile layout and permissions. Chat and voice/video call flows also need reliability and accessibility testing before claiming team outcomes.

What I chose not to ship yet

The portfolio shows the product's interface and intended workflows. Team names, task counts, event labels and status examples are illustrative and should not be treated as live activity or evidence of productivity improvement.
