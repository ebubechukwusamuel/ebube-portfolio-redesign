Product Design

Fundi

Fundi is a personal finance product with web and mobile interfaces. It brings balances, transaction activity, budgets, goals and AI-generated insights into one view, with account connection flows planned around open-banking providers. The interface uses a dark finance dashboard with emerald accents so money movement, progress and alerts are easy to scan.

View editable UI referencesView project source

Problem space

Money information is often scattered across account screens, notes and mental calculations. People need to see what came in, what went out, which budgets are getting close to their limits and what they can adjust next.

Design approach

I organised the core experience around a finance snapshot, recent activity, budget progress and insights. Transactions can be reviewed separately, while the AI insights area gives context to potential budget alerts, spending patterns and saving habits. Web and mobile screens follow the same dark palette and green highlight system.

Key design decisions

  • Put balance, income, expenses and savings rate together for a quick financial snapshot.
  • Keep recent transactions close to the summary so users can verify what changed.
  • Show budget progress using both amounts and a simple visual indicator.
  • Separate AI insights into alerts, spending patterns and practical saving prompts.
  • Treat bank linking and data refresh as trust-critical flows, with clear success, failure and stale-data states.

Product screens

These editable reference screens were recreated from the current Fundi app structure and design tokens. The displayed transaction rows and finance figures are illustrative sample data, not real user balances or performance results.

What I would validate next

I would test whether people understand transaction categories, budget progress and insight wording without over-trusting automated suggestions. I would also test account-link failure, duplicate transactions, stale balances, low-data states, privacy consent and how a user can correct an insight that does not match their situation. Metrics and user outcomes should only be added after real testing.

What I chose not to ship yet

The AI features are framed as decision support, not financial advice. Account connection and transaction refresh states need testing against real provider responses, and all demo values must remain clearly labelled as sample content.
